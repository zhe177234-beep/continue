# GraphRAG 与自主多 Agent

## 使用

1. 配置生成和向量模型，注册账号、建立知识库、上传资料（单文件最多 100 MiB，文字 PDF/PPT 最多 1000 页，扫描页 OCR 最多 20 页）。
2. 在“知识关系”页点击“构建 GraphRAG”。默认先抽取全部资料的关系，再建立实体、社区报告和实体向量。已有关系时可以取消“先自动提取关系”。
3. 等待后台任务完成，可以展开不同层级的社区报告核对逐字原文。
4. 在问答页选“GraphRAG 局部检索”问具体实体，或选“GraphRAG 全局汇总”总结整个知识库。全局问题在后台执行，结束后自动显示。
5. 在“自主任务”页描述目标，例如“解释学习率如何影响梯度下降，并给出原文引用”，选择最多检索轮数后启动。可查看角色动作与审查反馈，也可停止。

上传/删除资料、改变关系、更换模型后需重新构建。未建立 GraphRAG 时，Agent 仍能使用资料检索和学习记录工具。

## GraphRAG 实现

实现参考 [Microsoft GraphRAG 局部检索](https://microsoft.github.io/graphrag/query/local_search/)和[全局检索](https://microsoft.github.io/graphrag/query/global_search/)，使用本项目自己的存储、Ollama 传输和权限检查，不依赖微软官方包。

- 实体按 Unicode NFKC、空白和大小写归一化，合并相同规范名称，保留别名、原文片段及描述；可构建实体向量。
- 按关系证据次数建立加权图，通过 NetworkX Louvain 产生嵌套社区；零层为粗粒度主题，更高层为细分主题。没有关系的片段加入文档社区，所有片段均纳入索引。
- 每个层级的每个社区按最多 8 个原文片段分批生成报告，所有片段都会被处理。发现必须附上当前原文中的逐字摘录；模型无法给出有效发现时明确标记原文摘录回退。
- 局部查询结合实体名、实体向量、两跳邻域、社区背景和原文排名。
- 全局查询扫描所选层级的全部社区，将发现分批映射为相关要点，按分数合并，再用原文生成答案。模型只返回短整数证据编号，服务端映射真实片段 ID，避免模型抄错长哈希。
- 数据/关系指纹、模型名称和索引版本共同判断新旧；写事务保证原子发布。构建期间内容变化会失败，而不会发布旧快照。

这是完整的社区报告索引、局部查询和全局 Map-Reduce 工作流，不包含微软官方全部可选组件（如 Leiden、协变量抽取、DRIFT），不声称复现其质量指标。

## Agent 实现

规划者每轮读取目标、已有观察和审查反馈，选择资料 Agent、图谱 Agent 或学习 Agent，并产生下一次查询。回答 Agent 基于累计证据生成答案；独立审查 Agent 判断是否解决目标、是否有原文依据，并提出补查问题。未通过时继续规划，重复查询且无新问题时停止；通过时规划者可结束。

多个角色默认共用本地 CHAT_MODEL，每个角色有独立系统提示和结构化契约。它们是模型驱动的协作执行器，不只是页面上固定顺序的角色标签。事件记录只包含工具选择、查询、来源数量和审查结果，不展示内部推理。

工具仅能读取当前账号当前知识库的资料、图谱和学习记录，没有系统命令、任意 URL、资料删除或跨账号工具。工具名称、参数和返回结构都由服务器验证。

最多 8 轮检索，默认 4 轮；每次运行最多 64 次模型调用、1200 秒。证据不足时返回拒答；模型审查未通过时返回原文，outcome=needs_review。模型审查结合有效引用编号、证据指向和逐字摘录验证，但不能证明每个语义结论正确。

## 预算、停止和数据

每个知识库最多 20,000 片段；这不代表一次 GraphRAG 构建可以处理满额片段。关系提取和 GraphRAG 构建最多 1800 秒；社区报告默认最多 256 次调用，可通过 API 调整至 512。超过预算会明确失败，请拆分知识库，不会静默截断。单次模型调用限 90 秒，停止请求在当前调用结束后生效。

任务队列最多 8 个排队/运行任务；每个知识库同时一个。状态保存在 SQLite，刷新页面后可查看；服务重启会把中断任务标记为失败，不自动重复执行昂贵调用。删除资料清除派生报告和自主任务结果，并请求停止运行任务。

报告摘要与模型评分仍需人工核对。轻量 qwen3:0.6b 可以验证流程，复杂目标可能需要人工审查；更换大模型后应进行领域评测。
