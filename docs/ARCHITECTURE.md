# 系统、算法和实验设计

## 当前数据流

浏览器上传 base64 文件 → 解析与校验 → 按原始页分块（600 字，步长 500）→ SQLite 原文与三元组 → 检索排序 → 原文摘录与引用卡片。

查询与文档采用英文词项、中文二元字串分词。BM25 参数 k1=1.5、b=0.75；余弦基于词频向量；RRF 将两种排名按 1/(60+rank) 相加。graph 在混合检索基础上，给问题中明确出现的实体的一跳关系证据增加固定分值 0.1。当前参数为工程基线，尚未在独立开发集优化。

SQLite 三表：documents(id,name,digest,created)、chunks(id,document_id,page,position,text)、relations(chunk_id,subject,predicate,object)。事务限制总片段数量并处理重复上传；外键级联保障删除一致性。原文只保存在数据库，文件名不参与磁盘路径拼接。

## 目标架构与增量迁移

Vue 3 管理交互；Spring Boot 管理用户、课程、知识库和学习记录；FastAPI 承载解析、检索、生成与评测；PostgreSQL/pgvector 持久化并支持语义检索。迁移时先保留本版 API 与算法作为对照，避免重新开发时丢失验证能力。

模型层后续支持本地模型与兼容 API。生成必须返回受检索证据约束的引用；模型无关的离线摘录保留为降级链路。付费 API、模型部署、硬件依赖尚未接入本版。

## 毕设实验

1. 准备具有使用授权的多课程资料；标注至少 100~200 个问题、正确证据片段和参考答案，覆盖事实、关系、多跳与无答案问题。
2. 按文档或课程隔离开发集与测试集；测试集不用于选择参数。同一个问题的改写不能跨集合泄漏。
3. 比较 BM25、语义向量、混合、关系增强和动态路由；固定解析、分块、语料与生成模型。
4. 报告 Recall@K、MRR、证据引用准确率、无答案拒答正确率、回答事实一致性、延迟和资源占用。
5. 消融关系增强、路由、重排和分块策略；报告逐问题结果、失败案例及置信区间。
6. 三元组自动抽取后，单独标注并测量实体与关系准确率，避免把抽取误差与检索误差混为一谈。

`evaluate.py` 是三条人工问题的小型冒烟集，不能据其结果声称创新、先进性或算法提升。论文贡献应以真实对照实验为依据。

## 局限与部署边界

当前为本机单用户服务器；每次查询扫描全部分块，容量限制 2000。标准库 HTTP 服务没有生产级连接池、队列或资源隔离。PDF 解析在请求线程中进行，不能处理不可信公网文件。依赖版本采用范围约束，正式交付需锁定版本并审计。生产化需更换 ASGI 服务、增加身份认证、数据库隔离、速率限制、解析工作进程与反向代理。
